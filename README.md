## 5분 만에 돌려보기

```bash
pip install -r requirements.txt

cp .env.example .env          # .env 열어 OPENAI_API_KEY= 뒤에 키 붙여넣기

uvicorn as_chatbot:app --reload
```

| 주소 | |
|---|---|
| `http://127.0.0.1:8000` | 채팅 화면 — 일반 상담 |
| `http://127.0.0.1:8000/?as_id=AS-2026-00871` | 채팅 화면 — **개인화 상담** |
| `http://127.0.0.1:8000/docs` | **API 문서 (자동 생성)** |

### API 키 없이 확인만 하려면

```bash
MCM_MOCK=1 python as_chatbot.py --test
```

GPT를 호출하지 않고 검색·안전장치만 검증합니다. 무료·무제한.

## 어떻게 동작하나

**RAG** — 질문이 오면 우리 자료에서 관련 부분을 먼저 찾고, **그 자료만** GPT에게 주면서 "이걸로만 답하라"고 시킵니다.

```
질문  →  ① 우리 데이터에서 검색  →  ② [자료 + 질문]을 GPT에 전달  →  답변
                    ↓
           자료가 없으면 GPT를 호출조차 하지 않음
```

**GPT는 문장을 다듬는 역할만 하고, 내용은 전부 우리 데이터에서 나옵니다.**

### 지식베이스

| 구분 | 출처 |
|---|---|
| MCM 상품 | 공식몰 13개 카테고리에서 직접 수집 (`mcm_crawler.py`) |
| AS 안내 | MCM 공식 안내 문구 — 항목마다 `source` 기록 |
| 고객의 AS 접수 건 | 검색 대상이 아니라 **항상 자료 맨 앞에 고정 주입** |

마지막 항목이 개인화의 핵심입니다. `as_id`를 받으면 그 접수 건을 늘 들고 있으므로,
고객이 **"제 가방"**, **"언제 와요?"** 처럼 제품명을 말하지 않아도 무엇인지 압니다.

## AI가 지어내지 못하게 막은 6가지

| # | 장치 | 왜 |
|---|---|---|
| 1 | 자료가 없으면 **GPT 호출 자체를 안 함** | 근거 없는 문장이 생길 여지를 없앰 |
| 2 | 수선 금액 직답 금지 | 확정 단가 자료가 없는 상태에서 숫자를 말하면 사고. 견적 결과가 있을 때만 그 범위를 안내 |
| 3 | GPT 전송 **전에** 개인정보 정규식 치환 | 전화·이메일·주민·카드·주소. 프롬프트로 부탁하는 건 방어가 아님 |
| 4 | 여러 건이면 단정 금지 → 후보 제시 + 되묻기 | ↓ 아래 참고 |
| 5 | API가 실패해도 서버가 죽지 않음 | 429·타임아웃 시 대체 문구 |
| 6 | 로그·에러에서 API 키 마스킹 | 키 유출의 흔한 경로가 로그 |

### 4번이 필요한 이유 — 실제 데이터에서 발견한 것

```
MMKEAVE12CO001   Stark 사이드 스터드 비세토스 백팩    16 x 33 x 41
MMKEAVE14CO001   스타크 사이드 스터드 비세토스 백팩    13 x 30 x 38   ← 한글 표기만 다름
MMKEAVE01K8001   Stark 비세토스 사이드 스터드 백팩              ← 단어 순서만 다름
```

색상·본체·트림·안감이 **전부 같고 치수만 다릅니다.** 사진으로도 이름으로도 구분되지 않습니다.
수집한 상품의 **54%가 다른 상품과 이름을 공유**하고, 한 이름을 12개 상품이 나눠 쓰기도 합니다.

→ 그래서 이 챗봇은 상품명을 나열하지 않고 **색상·크기·상품코드를 함께** 보여준 뒤 어느 제품인지 되묻습니다.

## API

```
POST   /chat/stream         { message, session_id, as_id }   ← 권장 (SSE 스트리밍)
POST   /chat                같은 요청, 한 번에 응답
DELETE /chat/{session_id}   대화 초기화
GET    /chat/opening?as_id= 상담 첫 인사말 (GPT 미호출 · 즉시 응답)
GET    /health              상태 · 지식베이스 건수 · 연동 여부
GET    /docs                API 문서
```

```json
{ "message": "제 가방 지금 어디에 있어요?",
  "session_id": "web-a1b2",
  "as_id": "AS-2026-00871" }
```

- `session_id` — 프론트가 만들어 대화 내내 유지하면 맥락이 이어집니다
- `as_id` — 있으면 개인화 상담, 없으면 일반 상담

## 서비스 백엔드와의 연동

챗봇은 Python, 서비스 백엔드는 Java라 한 프로세스로 합칠 수 없습니다.
**별도 포트로 띄우고 HTTP로 연결**합니다.

```bash
SPRING_API_URL=http://서비스백엔드주소 uvicorn as_chatbot:app
```

| 상황 | 동작 |
|---|---|
| `SPRING_API_URL` 없음 | `as_dummy.json`(더미)으로 동작 |
| 서버가 응답하지 않음 | 로그만 남기고 **더미로 폴백** — 챗봇은 멈추지 않음 |
| 서버 정상 | 실제 DB 데이터 사용 |

서버 없이 연동을 검증할 수 있도록 **가짜 서버**를 함께 두었습니다.

```bash
python mock_spring.py     # 실제 DTO 필드·날짜 형식 그대로 흉내내는 테스트용 서버
```

## 파일

| 파일 | 역할 |
|---|---|
| `as_chatbot.py` | 챗봇 본체 + API 서버 |
| `spring_client.py` | 서비스 백엔드 연동 (실패 시 더미 폴백) |
| `mock_spring.py` | 연동 검증용 가짜 서버 |
| `mcm_crawler.py` | MCM 공식몰 상품 크롤러 |
| `collect_urls.py` | 카테고리에서 상품 URL 자동 수집 |
| `as_dummy.json` | 데모용 AS 접수 데이터 |
| `chat.html` | 테스트·시연용 화면 (실제 프론트 아님) |

| 문서 | 내용 |
|---|---|
| `챗봇_해설.md` | 챗봇이 **어떻게 답하는가** — 구조·설계 이유 |
| `서버_이해하기.md` | 서버가 **어떻게 도는가** — 실행법·오류 대처 |
| `현황.md` | 진행 상황·결정사항 (팀 내부용) |

## 환경변수

| 키 | 기본값 | 용도 |
|---|---|---|
| `OPENAI_API_KEY` | — | **필수** |
| `MCM_MOCK` | `0` | `1`이면 GPT 미호출 (검색·안전장치만 검증) |
| `SPRING_API_URL` | 없음 | 서비스 백엔드 주소. 비우면 더미 |
| `SPRING_API_TOKEN` | 없음 | 위 서버가 JWT를 요구할 때 |
| `ALLOWED_ORIGINS` | 전체 허용 | CORS. 배포 시 프론트 주소만 남길 것 |
